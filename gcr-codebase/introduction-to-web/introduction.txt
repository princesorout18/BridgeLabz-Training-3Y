1. DIFFERENCE BETWEEN FRONTEND, BACKEND, AND FULL-STACK DEVELOPMENT
============================================================

Web development is mainly divided into frontend development,
backend development, and full-stack development.

Frontend Development:
Frontend development deals with the part of a website that users
can see and interact with. It mainly uses HTML, CSS, and JavaScript.

Example:
The Amazon product page, buttons, menus, images, and search bar
are examples of frontend development.

Backend Development:
Backend development deals with the server-side logic of a website.
It handles requests, authentication, application logic, and
communication with databases.

Example:
When a user logs into Amazon, the backend processes the login
request and verifies the user's information.

Full-Stack Development:
Full-stack development involves both frontend and backend
development. A full-stack developer can work on the user interface,
server-side logic, APIs, and databases.

Example:
A developer who creates both the user interface and backend of
an e-commerce website is a full-stack developer.

2. CLIENT-SERVER MODEL IN WEB ARCHITECTURE
============================================================

The client-server model is a system in which the client requests
a service or resource and the server processes the request and
sends a response.

Simple Diagram:

                    HTTP Request
                         |
                         v
                +----------------+
                |     SERVER     |
                |   Web Server   |
                +----------------+
                         |
                         | HTTP Response
                         v
                +----------------+
                |     CLIENT     |
                |    Browser     |
                +----------------+
                         |
                         v
                    Web Page
                     Displayed


Explanation:

1. The user enters a website address in the browser.
2. The browser acts as the client.
3. The client sends a request to the web server.
4. The server processes the request.
5. The server sends a response back to the client.
6. The browser displays the requested web page.

3. HOW A BROWSER REQUESTS AND DISPLAYS A WEB PAGE
============================================================

When a user enters a website address, several steps take place.

Step 1: Enter URL
The user enters a URL such as:
https://www.example.com

Step 2: DNS Lookup
The browser finds the IP address associated with the domain name
using the Domain Name System (DNS).

Step 3: Connection with Server
The browser establishes a connection with the web server.

Step 4: HTTP/HTTPS Request
The browser sends an HTTP or HTTPS request to the server.

Step 5: Server Processing
The web server receives the request and finds or generates the
requested content.

Step 6: Server Response
The server sends files such as HTML, CSS, JavaScript, and images
back to the browser.

Step 7: Browser Rendering
The browser processes the HTML, CSS, and JavaScript and renders
the final webpage on the screen.

Flow:

User
  |
  v
Enters URL
  |
  v
Browser
  |
  v
DNS Lookup
  |
  v
Web Server
  |
  v
HTTP/HTTPS Response
  |
  v
HTML + CSS + JavaScript + Images
  |
  v
Browser Processes Files
  |
  v
Web Page Displayed

5. WHAT IS A WEB SERVER?
============================================================

A web server is a computer system or software that receives
requests from clients, processes those requests, and sends
web content back to the client.

When a user visits a website, the browser sends a request to
a web server. The server responds with resources such as
HTML pages, images, CSS files, or other data.

Main Functions of a Web Server:

1. Receives HTTP/HTTPS requests.
2. Processes client requests.
3. Provides web pages and files.
4. Communicates with applications and databases.
5. Sends responses to web browsers.

Examples of Commonly Used Web Servers:

1. Apache HTTP Server
2. Nginx
3. Microsoft Internet Information Services (IIS)
4. LiteSpeed Web Server
5. Caddy

Example:

Browser  ---- Request ---->  Web Server
Browser  <--- Response ----  Web Server

6. ROLES OF FRONTEND DEVELOPER, BACKEND DEVELOPER,
   AND DATABASE ADMINISTRATOR
============================================================

1. Frontend Developer:

A frontend developer develops the part of a website that users
can see and interact with.

Responsibilities:
- Create webpage structure using HTML.
- Design webpages using CSS.
- Add interactivity using JavaScript.
- Make websites responsive.
- Test the user interface.

Example:
Creating navigation bars, buttons, forms, menus, and product cards.


2. Backend Developer:

A backend developer works on the server-side part of an application.

Responsibilities:
- Develop server-side logic.
- Process user requests.
- Create APIs.
- Implement authentication.
- Communicate with databases.
- Handle application data.

Example:
When a user logs into a website, the backend checks the username
and password and returns the appropriate response.


3. Database Administrator (DBA):

A Database Administrator manages and maintains databases used
by an application.

Responsibilities:
- Create and manage databases.
- Store and organize data.
- Manage database users and permissions.
- Maintain database security.
- Perform backups and recovery.
- Monitor database performance.

Example:
A DBA may manage the database containing customer accounts,
orders, and product information for an online shopping website.

8. DIFFERENCE BETWEEN STATIC AND DYNAMIC WEBSITES
============================================================

Static Website:

A static website displays fixed content. The content generally
remains the same unless the developer manually changes the files.

Features:
- Simple structure.
- Mainly uses HTML and CSS.
- Content is usually fixed.
- Easy to host.
- Suitable for simple websites.

Example:
A personal portfolio or resume website containing fixed information.


Dynamic Website:

A dynamic website can generate or change content based on users,
databases, or other inputs.

Features:
- Content can change automatically.
- Usually communicates with a backend and database.
- Supports user accounts and interaction.
- Suitable for complex applications.

Example:
Amazon is a dynamic website because products, prices, orders,
user accounts, and recommendations can change.

Difference:

Static Website:
- Fixed content
- Simple to develop
- Usually does not require a database
- Suitable for portfolios
- Example: Personal portfolio

Dynamic Website:
- Changing content
- More complex
- Often uses a database
- Suitable for e-commerce websites
- Example: Amazon

9. FIVE WEB BROWSERS AND THEIR RENDERING ENGINES
============================================================

A browser rendering engine is the component responsible for
processing HTML and CSS and converting them into the visual
webpage displayed on the screen.

1. Google Chrome
Rendering Engine: Blink

2. Microsoft Edge
Rendering Engine: Blink

3. Mozilla Firefox
Rendering Engine: Gecko

4. Apple Safari
Rendering Engine: WebKit

5. Opera
Rendering Engine: Blink

Explanation:

Google Chrome:
Chrome uses the Blink rendering engine. Blink is part of the
Chromium project.

Microsoft Edge:
Modern Microsoft Edge is based on Chromium and uses Blink
for rendering web content.

Mozilla Firefox:
Firefox uses Gecko, Mozilla's browser engine.

Apple Safari:
Safari uses WebKit, Apple's browser engine.

Opera:
Modern Opera is Chromium-based and uses the Blink rendering engine.

Why Rendering Engines Matter:

Different rendering engines may implement some web standards
differently. Therefore, web developers test websites across
multiple browsers to make sure websites work correctly for
different users.
